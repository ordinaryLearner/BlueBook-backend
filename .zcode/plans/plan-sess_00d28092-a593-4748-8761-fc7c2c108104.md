## 目标

给 `posts` 表/帖子新增 `favourite` 属性：一个 JSONB 数组，存储所有"收藏过该帖子"的用户 ID。用户选择**双向同步**方案：收藏/取消收藏一个帖子时，同时维护现有的 `users.favorites`（帖子ID列表，保持不变、向后兼容）和新增的 `posts.favourite`（用户ID列表）。

实现将完全复用代码库中已有的 `posts.likes`（JSONB 用户 ID 列表，存储于帖子行）这一成熟模板。`favourite` 与 `likes` 一样，在返回的帖子 JSON 中是「uuid 字符串数组」（参照 README 说明：帖子的 likes、用户资料的 favorites 都返回 uuid 数组，只有评论的 likes 会展开成用户对象）。

## 涉及文件与改动

### 1. `src/config/database.js`（建表/迁移）
- 在 `posts` 建表语句/兼容段中，新增幂等迁移：
  `ALTER TABLE posts ADD COLUMN IF NOT EXISTS favourite JSONB DEFAULT '[]'::jsonb`（对齐 likes 的 `followers/fans/favorites` 写法，放在 posts 建表之后）。
- 在 `cleanNonArrayColumns` 清理段（现第 131-135 行）补一行：`await cleanNonArrayColumns('posts', 'favourite');`，把历史遗留的非数组脏数据纠正为空数组 `[]`。

### 2. `src/models/post.js`（模型层）
- 修改 `addFavorite`（现第 265-274 行）：在往 `users.favorites` 追加 postId 的同时，用同款幂等逻辑把 userId 追加到该帖子的 `posts.favourite`：
  `UPDATE posts SET favourite = CASE WHEN favourite @> $2::jsonb THEN favourite ELSE favourite || $2::jsonb END, updated_at = CURRENT_TIMESTAMP WHERE id = $1`（其中 $value = JSON.stringify([userId])）。
- 修改 `removeFavorite`（现第 277-288 行）：把 userId 从该帖子 `posts.favourite` 移除，用与 `removeLike` 一致的 `jsonb_agg ... WHERE elem::text <> $value` 写法，并更新 `posts.updated_at`。
- `isFavorited`（现第 291-300 行）仍以 `users.favorites` 判断即可（发起同步的入口没变，判断口径保持一致）。
- 修改 `addFavorite`/`removeFavorite` 需先确认帖子存在，避免写给不存在的 id——沿用 `favorite` controller 已有「先 `findPostById` 判断 404」前置校验，只需确保这两步在同一事务里保证一致性。为避免部分失败导致两面数据不对称，建议在本改动中对这两个函数内部用事务包裹两条 UPDATE（users + posts）。

### 3. 控制器与路由（`src/controllers/postController.js`、`src/routes/postRoutes.js`）
- **无需改动**。现有 `POST /api/posts/:id/favorite`、`DELETE /api/posts/:id/favorite` 已足够；它们调用 `addFavorite`/`removeFavorite`，改动后会自动同步 `posts.favourite`。
- 帖子查询（`findAllPosts`/`findPostById` 等均为 `SELECT p.*`）会自然把 `favourite` 字段带进返回的帖子 JSON，`favourite` 会随 seed 数据/新建帖子的 DB 默认值（`'[]'`) 存在；导出无需新增函数。

### 4. `README.md`（文档）
- 在「10.2/10.3 收藏/取消收藏帖子」小节补一句说明：收藏动作会同步写入该帖子的 `favourite`（收藏该帖的用户 ID 列表）。
- 在 post JSON 结构示例（约 330-375 行）、字段说明处补充 `favourite`（uuid 字符串数组，含义为收藏该帖的用户 ID 列表）。
- 在结尾 DDL（约 1612-1661 行）的 posts 定义中补 `favourite JSONB DEFAULT '[]'::jsonb`，并加迁移注释。

## 影响与验证
- **不破坏现有前端流程**：`users.favorites` 语义、`GET /api/posts/myfavorites`、用户资料的 `favorites`、收藏幂等与 404/400 行为全部保持不变；只是帖子行新增了镜像数组 `favourite`。
- **回读验证**：`GET /api/posts/:id`、`GET /api/posts` 等单帖子/列表接口返回的 JSON `favourite` 应为收藏该帖的用户 uuid 数组；对某帖子进行"收藏-取消收藏"再读，数组应随之增删且无重复、无脏数据。
- 手工/启动测试时验证服务能成功 `initDatabase()`（迁移幂等可重复执行）且收藏、取消收藏、查看帖子三个动作行为正确。
